# 实验报告 · 写作纪律与句式库（discipline）

> 配套 `sections.md`（逐节规律）与 `../writing-style.md`（全局写作纪律）。本文只写报告场景的增量规则。
> 锚句均为样本匿名化改写，可直接套用结构，禁止照抄内容。

## 1. 语气分层（报告特有的双轨制）

| 节 | 语气 | 人称 | 标志 |
|---|---|---|---|
| 原理/步骤/结果分析/结论 | 客观、克制、证据先行 | "本实验/本文/实验中"； hardware 报告用"本设计" | 数字、机制、因果链 |
| 总结及心得体会 | 反思、可带温度 | **第一人称"我/我们"** | 踩坑、领悟、收获 |

- 心得节的"我"不是散文化借口——每段仍要落到具体事件（调试了什么、发现了什么）。
- 结果分析里避免"我们觉得/我们认为"，用"分析表明/推测原因为/这说明"。
- 小组报告可用"我们"，但不要和"我"混用（B-12 全程"我们"，B-02 全程"我"）。

## 2. 数字与证据规范

1. **指标写全精度与样本量**："测试集准确率 96.00%（75 条样本，3 个错误）"；只写"很高/优秀"视为未完成。
2. **对比必须给差值**："87.06%，较参考模型 76% 提升了 11 个百分点"——不许只说"显著提升"。
3. **换算成直觉**（选做加分）："相当于 1023 张验证图片中约 28 张被错分。"
4. **十六进制/寄存器值等宽字体**（硬件报告）：`0x0000800F`；表格里十进制/十六进制并给（B-12 表4）。
5. **超参数齐全且注明出处**：epoch/lr/batch/优化器/损失函数逐项列出；"对应 xx.py 中 train 函数内的参数定义"。
6. **图必解读、表必引用**：正文出现"如图 N 所示/表 N 列出了"，图表编号全文连续；图题在图下、表题在表上。
7. **引用真实**：参考文献（学术骨架）GB/T 7714 或课程惯用格式；网页给完整 URL 与访问日期；不确定的文献标注"待核实"，禁止编造。

## 3. 报告专用句式库（按场景取用）

**步骤/方法**
- "首先……接着……随后……最后……"（一段式流水线，各用一次）
- "为了消除……的影响，对……进行了……处理"
- "参考代码仅使用了……，本次实验对此进行了……，以提升……"

**结果分析**
- "在 N 条测试样本上……准确率达到 X%，仅 k 个样本预测错误。"
- "从图 N 可以看出……（现象），说明/表明……（机制）。"
- "X 与 Y 存在较明显交叉误判，反映二者在……上的相似性。"
- "这一现象验证了……对……的调控机制。"
- "值得注意的是，……，这一现象可能源于两个因素：一是……二是……。"
- "造成这一结果的可能原因包括：……，这是主要原因；……；……。"
- "可见……波形符合预期。"（硬件验证收束句）
- "对比仿真与预测结果，可知两者所得……均一致，进一步说明……设计无误。"
- "由图 N 可知，……丢包率为 0%，说明……"（网络配置验证）

**结论**
- "本次实验完整实现了……从……到……的全流程，X% 的……验证了……。"
- "综合全部实验结果可以得出以下结论。首先……其次……再次……最后……"
- "整体表明，……设计正确，但需进一步引入……以解决……"（遗留问题钩子）

**心得**
- "最初……没有考虑……，导致出现……的问题，通过……解决了该问题。这让我明白……"
- "在反复调整……的过程中，我认识到……并非依赖单一技巧，而是……协同配合的结果。"

**改进建议**
- "可通过 X 对 Y 进行 Z，以……"（手段+对象+目的）
- "针对……的问题，可引入……"（对症下药）

## 4. 报告常见病（样本中真实出现，生成时必须避免）

| 病 | 样本例证 | 对策 |
|---|---|---|
| 无对照拔高 | "极强的泛化能力与分类性能"（B-02，无基线） | 无对比数据时降级为"在该任务上表现稳定" |
| 自我拔高 | "创新性地引入了余弦退火"（B-05，常规技术） | 常规技术用"引入/采用"；真创新才说"改进"且要给对照 |
| 套话收束 | "综上所述""达到了预期实验目标"高频出现 | "综上所述"每篇 ≤1 次且只在结论；"达到预期目标"要有数据支撑 |
| 段落复用 | B-15 作业一/二分析段整段重复；B-06 心得复述结果分析 | 同一论述全文至多出现一次，需要回指就写"见 X 节" |
| 编号错乱 | B-04"三．实验内容"与"六、实践内容"重复；B-13 节标题编号缺失 | 生成后按骨架逐节核对编号与标题 |
| 错别字 | B-13"上闽值"（阈值）；B-12 句子未写完（"分支地址计"） | 交付前通读一遍（checklist 硬性项） |
| 路径泄露 | B-06 源码含 D:\C&Cpp\Lab 1 绝对路径 | 代码示例用相对路径 |
| 口语比喻过量 | B-10"信心爆棚""偏科""双胞胎" | 全篇 ≤1 处，且加引号；正式分析句不用 |
| 图表堆积 | B-11 同类分布图 24 张全贴 | 同类图挑 6–8 张代表，其余进附录 |
| 心得空洞 | "受益匪浅""收获满满"无实例 | 每个收获配一个具体事件 |

## 5. "参考代码/指导书"场景的纪律

1. 指导书任务书原文（要求、加分项、注）**转述进"实验内容"节**，不加解读不改写要求。
2. 在参考代码上做改进时，永远先写"参考代码做了什么"，再写改动与动机（B-05 三段式）——这既是诚实也是得分点。
3. 报告里的"我改了什么"必须与代码 diff 一致；未提及的改动不要虚构。
4. 老师明文要求的报告要素（如"需指明学习率并与源码对应"，B-03/04）逐条自查。

## 6. 与全局写作纪律的关系

- `writing-style.md` 的四条正面原则（成段成体系/拒绝名词罗列/深入浅出/去 AI 味）在报告场景全部生效；本文 §1–§5 是其报告特化。
- 报告场景的"深入浅出"典型动作：公式后紧跟一句人话解释（B-02"熵的实际意义表示是……"）；机制解读用因果链而非术语堆叠。
- 生成正文前载入 `writing-style.md`；交付前过 `checklist.md`。
