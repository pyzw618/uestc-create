# 实验报告 · 逐节写法规律（sections）

> 证据来源：16 份成电实验/课设报告样本（代号 B-01…B-16）。代号体系与证据强度见 `references/evidence.md`。
> 每条规律标注印证样本；标注 ★ 的规律有 ≥3 份样本交叉印证。

## 0. 骨架族谱（先认骨架，再写内容）

同一所学校、不同课程的报告骨架差异很大，**动笔前必须先识别用户属于哪一族**：

| 骨架族 | 识别特征 | 章节 | 样本 |
|---|---|---|---|
| 官方标准 12 节 | 封面"标 准 实 验 报 告" | 一实验室名称…十二改进建议 | B-06★、format.md 骨架 |
| 官方"实践"变体 | 封面"标 准 实 践 报 告"，全部"实验"→"实践" | 同上换名 | B-02/03/04/05 |
| 官方六节压缩 | 12 节压成 6 节 | 项目名称/学时/技术手段/内容及步骤/总结心得/改进建议 | B-16 |
| 官方扩展变体 | 插入"实验源码"节，后续重编号 | …八步骤/九源码/十结果分析… | B-06 |
| 计组完整版 | 每实验 7 节 | 名称/学时/内容目的/原理/器材/步骤/数据分析 | B-15 |
| 计组极简版 | 每实验仅 2 节 | 实验名称 / 实验数据及结果分析 | B-07 |
| 教师自定学术型 | 编号用"一."（点号） | 问题描述/方案描述/算法公式/计算指标结果/改进计划/参考文献 | B-08/09/10/11 |
| 课程设计型（数集I） | 编号续写（从六、起） | 指标要求/概念解析/模块设计与调试/总结/附录 | B-01/14 |
| 课设报告（电路类） | 小组表封面 | 设计目的/设计原理/仿真设计/总结/仿真误差分析 | B-13 |

- **合并型**（★3 种形态）：①一文件内每个实验重复完整骨架（B-04、B-08~B-11 基础+挑战、B-06、B-16）；②封面/信息页一次，实验顺次排列（B-07、B-15）；③挑战实验 = 基础实验骨架的复制，标题改为"实验报告N：挑战实验"（B-08）。
- **优先级铁律**：老师下发模板 > 同课程历史报告 > 官方标准骨架。工作区里有模板就逐节对齐它的节名与编号（含"六、"起始的续写编号，B-01/14）。

## 1. 封面

★ 三种署名形态：单人（姓名/学号/指导教师一行，B-02 类）；结对（两行"学生姓名/学号"，B-12）；小组（表格或列表，4 人逐行列出，B-01/14）+ 小组成员表（B-13）。
★ 封面信息行随课程变化：实验地点/实验时间（B-02~05、B-16）、测试日期/测试设备（B-01/14，设备写到软件版本号"Vivado 2024.1"）、日期（B-15）。
- **任务摘要框**（B-12）：封面下方"任务及完成情况摘要(不超过400字)"——三段式：做了什么（基线→扩展）→ 关键机制（一句一个）→ 验证结论（"输出波形符合预期……达到了实验设计要求"）。
- **评分栏**：报告评分/指导教师签字留在封面或文末，**留空**（B-02、B-12 另有"功能实现及答辩85分/报告15分"权重表）。

## 2. 逐节写法规律

### 2.1 实验原理 / 设计原理

★ 三种深度档位（按课程要求选，宁欠勿过）：
1. **教材式概念引入**（B-02/03/13）：术语全称→名称由来→基本思想完整闭环→关键公式→"实际意义"解释。适合算法/电路课。句式："X 算法的核心思想就是……下面先定义几个要用到的概念""其基本思想是：……这种过程反复进行，直至……为止"。
2. **自写原理 + 本实验参数落地**（B-15、B-05）：概念一句 + **落到本实验的具体数值**（"本实验中的多层感知器的结构是：输入层-隐层-隐层-输出层""控制信号逻辑表达式 SUBctr=ALUctr[2]"）。适合课程允许简写的场合。
3. **极简档**（B-06）：只填工具名（"C语言"）——课程不要求时不必硬凑，但要在内容节里补足思路。
- ★ 原理节给"为什么这样设计"（B-01：小卷积优于大卷积的感受野论证；B-14：先立 BYTE/对齐概念再设计）。公式尽量用 Word 公式对象或代码体内联（B-15 用 `SUBctr = ALUctr[2]` 内联，避免公式对象丢失风险）。

### 2.2 实验目的 / 内容 / 技术手段

★ 目的一行到两行，动词开头（"编程实现 X；理解 Y"，B-02/03/05★）。
★ 内容 = 任务书转述 + 要求列表（"要求：（1）提交源代码……（3）需画出决策树"）+ 加分项注（"注：如用到了剪枝……（加分项），请加以说明"，B-02/04★）。数据规格写全（"75*5，第5列为标签"）。
- 技术手段节（B-16 骨架）：技术清单 + 一句话作用（"VLAN 技术：通过划分 VLAN 将不同 PC 划入不同广播域，实现逻辑隔离。"）。
- 方案描述节（学术骨架，B-08）：逐模型一句"是什么+为什么适合" + 引号技术路线（"整体技术路线遵循'数据加载→预处理→多模型训练→评估对比'的流程"）。

### 2.3 实验步骤

★ 两档：
1. **一段式流水线叙述**（B-02）：整段连叙，函数名内嵌，连接词"首先/接着/随后/最后"各用一次。适合步骤简单的软件实验。
2. **分段式带动机**（B-03/05）：一段一个主题（数据→结构→训练→评估），**每个选择给理由**（"为了消除不同特征量纲差异对模型训练的影响""批次大小从32调整为16，以利于模型泛化"）。改进型报告用"参考代码做了什么→我改了什么→为什么改"三段式（B-05）。
- ★ 超参数必须写全并**注明源码出处**（"学习率 lr 为 0.01，对应 learn_test.py 中 train 函数内的参数定义"，B-03；任务书明文要求时是硬性规定，B-04）。
- 硬件类步骤 = 设计过程叙述（"首先进行架构重组。将单周期内顺序完成的所有操作，划分为……五个独立的流水阶段"），配架构图（B-12）。

### 2.4 代码呈现

★ 四种形态：
1. **源码内嵌 + 骨架重编号**（B-06）：整段源码进"九、实验源码"，可保留调试注释；**注意脱敏**（去掉本机绝对路径 D:\...）。
2. **逐模块说明书**（B-12）：不贴代码，每模块写"核心功能为：……"+ 收尾定位一句（"该模块是 CPU 的'指挥中枢'"）；代码进附录。
3. **代码 + 文字说明配对**（B-15/16）：关键函数逐个"函数负责……首先……随后……"；数据结构用表格（类|成员|说明）。
4. **贴代码声明**（B-15）："报告中所有代码均采用可复制格式（文本而非图片），方便老师查阅"——读者意识加分项。
- ★ 激励/测试代码的**预期值写进注释**（"//测试当S=0时目标输出应为 0"，B-07/15★）；指令序列逐行注释预期寄存器值（"// $t0 = 0x20+0x10=0x30, PC=0x00000020"，B-15）。
- 附录代码带**修改标记**（"修改部分用黄色底色标出"，B-14）。

### 2.5 实验数据及结果分析（报告的心脏）

★ 通用开场：一两句交代实验设置（数据划分、重复次数），然后进入分析。数字永远具体到百分位（96.00%、0.9653、+4.8 个百分点）。

**范式 A：多视角归因**（B-03/05/08/10★）——结果好时拆解原因：
- 三视角（B-03）：总体数字 → 归因1数据预处理 → 归因2超参数 → 归因3算法实现，每条因果完整（"该学习率既不会因过大导致震荡不收敛，也不会因过小导致收敛速度过慢"）。
- 四视角（B-05）：总体对比（87.06% vs 参考 76%，"提升了11个百分点"）→ 训练曲线 → 混淆矩阵逐类 → 置信度分布 → 一句话总归因（"并非单一因素所致，而是……协同作用的结果"）。
- 混淆矩阵解读句式："X 与 Y 存在较明显交叉误判，反映二者在……上的视觉相似性"（B-04）；"对角线数值均超过 950，准确率高于 95%"（B-04）。

**范式 B：消融/对比**（B-10/11★）：每个维度"现象（数字）+机制归因"（"0.1 的学习率过大导致模型无法收敛，准确率仅 20% 左右"）；迭代次数类实验收尾给权衡结论（"并非越多越好，需在偏差和方差之间取得平衡"，B-11）；参数扫描给"高性能平台区"概念（B-09）。

**范式 C：逐指令/逐周期走读**（B-15/07★，硬件）：每条指令"动作→依赖→机制→数值验证"（"此时 $2 是前一条指令的写回目标，于是将……ALU 结果（20）直接前推至……使其能正确计算 20+3=23"）；逐周期大表（PC|指令|控制信号|数据信号|执行分析）；逐操作码一行一条（"操作码 001，对应 add……Overflow 为 1.符合预期"）。

**范式 D：波形/测试节拍**（B-07/01/14★）：`模块代码→激励代码→波形图→结果信号表→"可见……波形符合预期"`；FPGA 课设加**三件套**（资源/功耗/时序，各走"概念定义→本设计数值→判断"循环，B-01："0.176W 是一个非常低的功耗值，属于典型的低功耗设计""静态功耗占 90%……完全符合预期"；时序推导到最高工作频率 152.3MHz）。

**范式 E：配置命令型**（B-16）：拓扑图+IP 规划表 → CLI 命令块 + **每块后"说明：……"** → 每个测试"由图 N 可知……丢包率为 0%，说明……"；路由表逐行解读（"其中'[120/1]'表示管理距离为 120（协议默认值）"）。

**范式 F：负结果（失败也要写好）**（B-11★）：对照基准（"ROC-AUC 51.19%，接近随机猜测水平（0.5）"）→ 量化差距（对照 Leader Board Top1）→ **有序归因并标主因**（"造成这一结果的可能原因包括：……，这是模型性能不佳的主要原因；……；……"）→ 改进计划逐条对治。失败报告的归因比成功报告更有价值。

**范式 G：结果验证型**（B-06）：结果数字与预期不符时——解释原因（"由于 IP 可能分属两个及以上的子网，所以最后一列的和（33）比全部 IP 数（30）多"）→ 手动验证方法 → "故结果合理"。反常但正常的现象要点明（"丢包率为 25%，后续通信正常。这属于正常现象"，B-16）。

**反常现象解读**（★B-09/16）：不回避，给候选解释（"值得注意的是，验证损失始终低于训练损失，这一现象可能源于两个因素：一是……二是……"）。

**图表纪律**（★）：每张图后必有一段解读，禁止裸贴图；图题格式"图N XXX图"（B-01"图2 反斜线'╲'仿真波形图"）；表题在表上方"表N XXX"（B-08/11）；同类图 24 张全贴是大忌，挑代表性 6–8 张，其余进附录（B-11 教训）。

### 2.6 误差分析 / 仿真误差分析

★ **"问题 → 分析 → 改善方法"三段式**（B-13）：问题一句话现象（"输出信号有上升或下降沿的倾斜"）→ 编号归因（器件级："单位增益带宽相对较低……无法瞬间完成翻转，所以会形成类似梯形的过渡"）→ 改善（"减小 R2 的阻值，增加滤波电容"）。
- 硬件误差分析归因到器件参数与数据手册（B-13）；软件实验的"误差"多为失败案例分析（范式 F/G）。
- 修 bug 闭环（★B-07/14/15）：现象（具体错误值）→ 根因定位到代码行（"其根本原因在于……只判断了访问大小，完全忽略了对……的对齐检查"）→ 修改 → 复测数值（"$1 的值已及时更新为 5，所得结果为正常值 0x00000005|0x0000800a = 0x0000800f"）→ 前后对比。

### 2.7 实验结论

★ 四件套：全流程一句回顾 → 数字结论（复述关键指标）→ 归因/意义一句 → 局限或下一步一句（B-02~05★）。改进型报告逐项确认每项改进的效果（B-05："引入 BatchNorm 层可显著加速收敛；将优化器由……有助于……"）。
- 编号结论（B-09/11）："综合全部实验结果可以得出以下结论。首先……其次……再次……最后……总体而言"，每条带实践建议。
- 简短也合法（B-06："编写的程序可正常运行并完成既定目标。"）——课程不要求时不必注水。
- 结论 ≠ 摘要：结论写"做出了什么、意味着什么、还剩什么"。

### 2.8 总结及心得体会

★ **语气切换**：本节用第一人称"我"（B-02/03/04/05/06/12/16★），与结果分析的客观语气分工。
★ **踩坑记录是灵魂**：具体问题 + 排查过程 + 解决 + 领悟（B-03："最初实现 softmax 时没有考虑数值稳定性，导致指数溢出，通过修改为减去最大值的方式解决了该问题。这让我明白……"；B-16："忘记执行 no switchport 命令导致接口无法配置 IP 地址……通过查阅资料和反复调试"）。
- 领悟要具体（"数据质量决定模型上限"式一句提炼可以，空洞的"受益匪浅"不行）。
- 心得与结果分析**不要整段重复**（B-06 的重复、B-15 作业一/二的分析段重复是反面教材）。

### 2.9 改进建议

★ 每条"手段+目的"成对，写具体技术名（B-03："可通过网格搜索……针对 max_depth、learning_rate 等关键参数进行精细化搜索"；B-05："引入 Mixup、CutMix 等混合增强技术，提升模型鲁棒性"）。
- 与自己报告的局限对应（B-11 的失败→改进逐条对治是最佳实践）。
- **没有就写"无"**（B-16 三份都写"无"）——不硬凑。

### 2.10 思考题 / 作业

- 硬件课作业常为指令序列推演：逐条注释预期值 → 与仿真对照（B-07/15："对比仿真与预测结果……均一致"）。
- 算法课思考题按"问题实质 → 结合本实验作答"，引用实验数据佐证。

## 3. 横向纪律（跨节生效）

- **实验间衔接**：前一实验的遗留问题在下一实验解决（B-15："仿真也暴露出潜在的数据冒险问题……需进一步引入转发与阻塞机制"——为实验四埋钩子）。
- **合理性检查**：输出范围/数量级核对（"预测值的范围与训练标签基本一致，表明模型的输出处于合理的数值区间内"，B-09）。
- **准确率换算成直觉**（B-08）："这意味着在 1023 张验证图片中，仅有约 28 张被错误分类。"
- **测试递进设计**：先分方向/分单元验证，再综合场景（B-01："在确定四个方向上的胜利判断逻辑无误后，对平局、冲四、活三、活四……并在下棋过程中穿插了非法操作"）。
- **防泄露声明**（B-04）："为避免测试集泄露，从原始训练集中划分出后 5000 张作为独立验证集。"
