# B 路线：实验报告（lab-report）

> 状态：**v1（阶段 2 完成版）**。流程分「必守检查点」（⚠ 标注）与「弹性做法」两层；弹性部分按用户实际情况取舍，不强行走满全流程。

## 输入与产出

- **输入**：实验数据/结果（xlsx、截图、串口日志、仿真波形等）、代码、实验指导书或课程要求（可选）、老师模板（可选）。
- **产出**：.docx 报告（+按需转 PDF）。用户明确要求 LaTeX 时：借用 `assets/course-papers/latex/` 模板骨架，按 `references/lab-report/format.md` 的十二节映射章节，先与用户确认章节对照再动工。**前置提醒**：用户还没做实验/没数据时，先说明本路线接收的是成果呈现，请先完成实验。

## ⚠ 第 0 步：模板检查与一次询问（硬性，每次会话至多问一次）

1. 扫描工作区：有无老师下发的报告模板/格式要求（.doc/.docx/.pdf，关键词：报告模板、实验要求、评分标准）？
2. **工作区没有 → 问一次**：「用标准实验报告模板，还是你把老师的模板/要求发我？」用户答复后不再重复问。
3. 判定结果记为 `骨架源`：`用户模板`（最高优先）> `标准模板` > `同类课程惯例`（仅当用户说"随便/按常规"）。
4. 顺带确认 `config/user.yaml` 是否已填（封面需要时）。

## 第 1 步：识别骨架与实验形态

对照 `references/lab-report/sections.md` §0 骨架族谱判定：

- **骨架族**：官方 12 节 / 实践变体 / 六节压缩 / 计组完整版 / 计组极简版 / 教师自定学术型 / 课设型 / 用户自定义。用户模板的节名与编号（含"六、"续写、"一."点号风格）逐字沿用。
- **实验形态**：单实验 / **合并型**（基础+挑战、多实验）→ 见 §合并型分支。
- **领域形态**（影响结果分析范式，见 sections.md §2.5）：软件/算法（范式 A/B/F/G）、硬件/FPGA（范式 C/D）、网络配置（范式 E）、混合。
- 弹性：判不准时问用户一句"哪个课程、有没有样例报告"，不要猜。

## 第 2 步：解析输入

- 指导书（.doc/.docx/.pdf）：转 docx（`engines/docx` §6）或提取文本 → 列出**数据项清单**：任务与要求、必填章节、加分项、明确规定的报告要素（如"需指明学习率并与源码对应"）。
- 数据文件（xlsx/csv）：读列名与量纲，记下关键数字（样本量、指标值）；数据不完整时列出缺口问用户要，**不编造数据**。
- 代码：提取函数清单、超参数、关键改动（用于步骤节与"与源码对应"标注）。

## 第 3 步：骨架生成

| 判据 | 做法 |
|---|---|
| 用户给了模板 | 复制用户模板为底版，只填内容（保护其格式） |
| 标准骨架 + 官方 12 节 | 复制 `assets/lab-report/标准实验报告.docx` 填充（首选），或用 `标准实验报告骨架.docx` 占位符版 |
| 其他骨架 | 按 `format.md` 参数用 python-docx 程序构建（Heading 样式、eastAsia 字体；生成后可 `scripts/cjk.py fix` 兜底） |

- 合并型：按形态①每实验重复完整骨架（顺序拼接）或形态②信息页一次实验顺次排（见 sections.md §0）。
- 封面字段从 config 读取；结对/小组报告按用户提供名单。

## 第 4 步：逐节生成（先载入 writing-style.md）

写作顺序建议：内容/步骤 → 数据及结果分析 → 结论 → 原理 → 心得 → 建议（先易后难，分析节是核心）。

- 每节先查 `sections.md` 对应小节的范式；结果分析按领域选范式 A–G，数字具体、每图必解读。
- 代码块按 `sections.md` §2.4 呈现（预期值进注释、关键改动标记、绝对路径脱敏）。
- 心得节按 `discipline.md` §1 切换第一人称；没有真实踩坑过程时**留占位并向用户要素材**（"调试中遇到过什么问题？"），不虚构踩坑。
- 每节生成完即时过 `writing-style.md` §5 自查（该节的禁用词/名词堆砌/证据挂靠）。

## ⚠ 第 5 步：交付前自检（硬性）

先跑机检 `python evals/check_deliverable.py <成品.docx>`（占位符/禁用词/模糊数字/个人信息），hard fail 清零。
按 `references/lab-report/checklist.md` A→D 逐项过；向用户报告结果（全过 / 未过项+原因）。需要独立判定时派 `evals/grader.md`。
用 `python scripts/render_preview.py <成品.docx>` 转 PDF 并出逐页 PNG；有视觉验收能力时按 `engines/visual-judge.md` 自查。

## 合并型分支（基础+挑战 / 多实验）

1. 每个实验独立成套骨架；实验间用一句衔接（前一实验遗留问题 → 后一实验解决，见 sections.md §3）。
2. 挑战实验 = 基础骨架复制 + 标题改"实验报告N：挑战实验"（教师自定骨架族）；官方骨架族则各自完整 12 节或按用户模板。
3. 公共内容（数据集介绍、环境配置）只在首个实验出现，后文引用"见实验一"。
4. 各实验的总结及心得**不合并**，分别写，避免复用粘贴。

## 边界（明确拒绝/转介）

- 帮做实验本身、编造实验数据、编造调试经历 → 拒绝，说明原因，提供"如何把真实过程整理成报告"的帮助。
- 用户要的是开题/中期/结题规划 → 转 D 路线；要汇报 PPT → 转 A 路线。
